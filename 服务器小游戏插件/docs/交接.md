### ①' ✅ MurderMystery 的 `tpl:` 收尾（2026-11-01 已完成）

**根因、修法、实测数字都在 `docs/坐标解耦清单.md` §6（已重写）与 §9。** 一句话版：

- 真根因不是"reload 没重读"（`reloadConfigAndRescanGold()` 里就有 `load()`），而是
  `world_key: tpl:xxx` 写进 `==: org.bukkit.Location` 后，**YAML 解析阶段**就抛
  `IllegalArgumentException: unknown world` → 节点被置 null → `convertMapsToSections` 的
  `set(key, null)` 把键删掉 → 关服 `saveConfig()` 写出 `圣诞工厂: {}`。
- 修法：**房间世界写字符串 token**（`pos1: 'tpl:mm_test,x,y,z,yaw,pitch'`），固定世界照旧写原生 `Location`
  （`Worlds` 1.7.3 读写都支持两种形态）；另外 `load()` 末尾补 `publishRegions()`，reload 后才会重发地盘。
- 实测：基线 24 块 / 19 游戏 → `tpl:` 无房间时 20/18 → `hub room create mm_test mmroom` + `mm reload` 后
  **24 块 / 19 游戏**（MM 4 块绑到 `room_mmroom`），ERROR 0，关服后 16 处 `tpl:mm_test` 原样保留。

> ⚠️ 老办法（把 `world_key` 改成 `tpl:xxx`）**已经被判定为不可行**，别再照它改别的游戏。
> 要给线上 MM 上 `tpl:`，必须先把配置里的坐标改成字符串 token 形态（§6.4 有两种办法）。

## 2.5 （已证伪）"`/hill start` 有时不开局"

**不是产品 bug**：是测试里 `hill start` 早于假玩家入队发出的，`waiting` 为空导致不开局。
加日志复现两次，倒计时路径健康（3→2→1→0 → 回调 → RUNNING）。详见 `改动记录.md`。
教训：`fakeclient` 登录延迟 2–20 秒，"第 N 秒发命令"的时间表不可靠。

三次实测 1 成 2 败。**已排除**：玩家没进队列、场地未就绪、会话终态、ERROR。
**嫌疑**：`StartCountdown.begin()` 在 key 已有任务时直接 `return true`（不做事），
而被 `cancel()` 的任务不会触发 `onFinish` → 表现为"在倒计时但永远不开局"。
详见 `改动记录.md` 对应条目。**排查入口**：`hill start` 路径上谁调了 `countdown.cancel()`。

## 3. 结构性的教训（别再踩）

1. **`ConfigurationSection#createSection` 是"新建+覆盖"，不是"获取或创建"**。
   用它保存场地会把磁盘上的坐标整段清掉（实测丢过两次真实数据）。
   统一用 `Worlds.getOrCreate(parent, path)`。
2. **保存时"读不出来"必须表现为"不动它"**，绝不能 `set(key, null)`。
3. **`sec.isConfigurationSection(key)` 不能当作"这个键存在"的前置判断** ——
   坐标是带 `==: org.bukkit.Location` 的序列化 Map，加了会把整批插件误判成"没配置"。
4. **批量正则替换后必须编译** —— 今天两次误伤了非坐标的 `set` 调用。
5. **验证前先还原配置**（硬规则第 5 条）。
