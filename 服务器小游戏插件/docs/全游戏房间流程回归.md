## 说明

1. **17 个端到端通过**：房间创建 → 玩家进房 → 游戏在**房间世界**里开局。
   其中子游戏是"派对开局后委派到房间世界"（日志 `已委派 xxx 到房间 room_xxx_1 的世界 ...`），
   独立游戏是自己建会话（`buildrun/红地板 [WAITING] 2 人` 等）。
2. **5 个被配置禁用**：`ArcadeParty/config.yml` 里这 5 个是 `enabled: false`，
   派对的"可选小游戏池"与房间子游戏取交集为空 → 直接返回 `这个房间里没有可玩的小游戏`。
   **不是代码问题**：插件出厂默认配置里没有任何 `enabled: false`（`gameEnabled()` 缺省 true），
   是服务器上手动的。`digtobottom` 已在测试副本验证：打开后立刻能跑。
3. **没有代码问题的游戏了**。

## 这一阶段修掉的 9 个真问题

| # | 问题 | 症状 |
| --- | --- | --- |
| 1 | `startParty` 读字段 `lobby` 而非 `getLobby()` | 倒计时到点静默 return，永不开局 |
| 2 | 框架"进房前重载"**每个玩家都触发** | 第二次重载调 `load()` → `waiting.clear()` → 前一个玩家被挤出队列，永远凑不满 2 人 |
| 3 | `createForMap` 不设房间场地名 | `{arena}` 为空 → `buildrun join`（少参数）→ 游戏只回"用法" |
| 4 | 8 个游戏的 `reload` 分支**插进嵌套 switch** | `/buildrun reload` 回"未知子命令" → 场地从未重解析 → `isReady()` 永远 false |
| 5 | `maps.yml` 用 `digdown`，其它三处用 `digtobottom` | `isSubGame()` 为 false → 没套壳成派对 |
| 6 | `games.yml` 的 `mm join` 少了 `{arena}` | `/mm join` 命令层就回"用法"，manager 根本没被调用 |
| 7 | `TNTBattleArena.parse` 用 `Bukkit.getWorld` | 不支持 `tpl:` 令牌 → 场地永远"未配置" |
| 8 | 回归夹具缺隔离环境 / 控制台脚本太短 | 跑到一半被占端口打断；服务器在派对开局前关服 |
| 9 | 断言被 ANSI 颜色码打断、取日志末尾 | 明明有会话却判成"无" |

## 还没验的（下一阶段）

- **对局结束 → 房间销毁**（D25）：本轮只验到"开局"，没有一局打完。
  目前只有 `DuelArena` 与 `HillKing` 显式写了"对局结束删房间"，
  其它游戏靠 300s 空置回收兜底 —— 这块要**收敛到框架层**（`GameSession.end()` 负责销毁对局房间）。
- **菜单由注册表派生**（R1）：现在游戏 key 在 `maps.yml` / `games.yml` / `ArcadeParty config` /
  `players.yml` **四处各写一遍**，天然容易不一致（本轮已踩到两次）。
