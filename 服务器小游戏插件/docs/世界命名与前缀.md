# 世界命名与前缀规则（计划，未实现）

> 来源：用户 2026-11-01 的要求 —— 模板世界与游玩世界各用各自的前缀；
> `/gw` 创建世界时若名字没带前缀则**默认补模板前缀**以防冲突，除非管理员显式强制。
> 状态：**计划**。实现时机见 §5（我决定：与 R3 选房 UI 同批）。

---

## 1. 前缀家族（三段命名空间）

| 前缀 | 谁创建 | 用途 | 开服时是否加载 |
| --- | --- | --- | --- |
| **`tmpl_`** | 管理员 `/gw create`（默认）；或房间引擎的模板登记 | **模板世界**：设计者编辑的地图源，只被复制、**永不当场地加载** | ❌ **不自动加载**（需要时手动 `/gw load`） |
| **`room_`** | **只有房间引擎**（`RoomManager`） | 房间实例：从模板复制出来的动态世界，用完即删 | ❌ 不自动加载（由引擎按需建/删） |
| 其它（`world_*`、`world`、历史名） | 历史遗留 / 主城 | **持久游玩世界**：主城与老场地 | ✅ 按现有规则自动加载 |

**为什么必须分前缀**：房间化之后，"这块地是世界模板、还是一份临时实例、还是长期存在的主城"
是**三种完全不同的生命周期**。靠名字前缀区分比查配置表更可靠 ——
引擎、`doctor`、运维清理脚本都能一眼看出一个目录是干什么的。

## 2. `/gw create` 的前缀规则

现在的行为（`GameWorldsPlugin`）：`/gw create <世界名> [void]`，名字强制小写、校验 `[a-z0-9_-]`。

**改成**：

```
/gw create <名字> [void]           # 名字没有已知前缀 -> 自动补 tmpl_，并告知最终世界名
/gw create --force <名字> [void]   # 原样创建，不补前缀（管理员明确知道自己在做什么）
```

规则细节：

1. **已知前缀**指 `tmpl_` / `room_` / `world_` 三者之一（以及裸名 `world`）。
2. 名字**不带**任何已知前缀、且没给 `--force` → 实际创建 `<tompl>`… 即 **`tmpl_` + 原名**，
   并在回执里写清楚：`已创建模板世界 tmpl_xxx（自动补前缀；要原名请用 --force）`。
3. 名字带 `room_` → **一律拒绝**（即使 `--force`），提示"房间世界由房间引擎创建（`/hub room create`）"。
   理由：`room_` 是引擎独占命名空间，手建会和房间回收/删除逻辑打架。
4. `--force` 只对"要不要补前缀"生效，不改变 `room_` 的拒绝、也不改变名字合法性校验。

## 3. 配套：`tmpl_` 世界不自动加载

这是**必须一起做**的一条，否则规则自相矛盾：默认补 `tmpl_`，而 GameWorlds 又会把
配置里登记的世界全部在开服时 `createWorld` —— 模板就被加载了（违背"模板永不加载"）。

做法：`GameWorlds` 读到名字以 `tmpl_` 开头的条目时，登记为**托管但不自动加载**
（`load: false` 语义），需要时用 `/gw load <名字>` 手动加载（设计者建图时用），
`/gw unload` 收回。

## 4. 需要同步的地方

| 位置 | 改什么 |

| `GameWorldsPlugin` | `create` 的前缀规则；`tmpl_` 不自动加载；`list` 按前缀分组显示 |
| `RoomManager` | 已用 `room_` 前缀（`ROOM_PREFIX`）；模板登记校验 `folder` 必须以 `tmpl_` 开头 |
| `tools/region-report.py` | 区域表可按前缀区分"模板世界 / 房间世界 / 持久世界" |
| `/hub doctor` | `[世界]` 段按前缀分类统计；`[房间]` 段已有 |
| `docs/房间引擎设计.md` §1 | 目录约定已写 `tmpl_` / `room_`，补一句"由 `/gw create` 强制执行" |

## 5. 实现时机（我决定）

**与 R3（选房 UI）同一批做**，理由：

- R3 要让玩家"选地图 → 建房间"，**第一步就是列出可用模板** → 必须有可靠的"哪些目录是模板"的判定，
  而前缀是最便宜的判定方式（不用读模板登记表，也不依赖配置是否被手改）。
- `tmpl_` 不自动加载这条，直接影响"开服时到底加载了几个世界"（也直接影响那 3.6s 的启动存盘开销）。
- 两件事都改 `GameWorlds` + `RoomManager`，合并做比分开做少一轮构建/冒烟。

**在此之前不改**：现在 `tmpl_` 世界在 `templates.yml` 里是手工登记的（`folder: tmpl_xxx`），
房间引擎只把它们当"复制源"，不加载，所以当前行为是正确的；缺的只是 `/gw create` 的便捷入口与强制力。
