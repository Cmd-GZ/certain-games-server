# 房间引擎骨架设计（R1）

> 承接 `docs/模板世界方案评估.md`（已实测：IO 不是瓶颈、热建世界可行、复制模板必须删世界身份）。
> **本文只设计「房间引擎」本身**：模板登记、房间创建/销毁/回收、上限、管理命令。
> **不碰任何游戏**——把 HillKing 接进房间是 R1.5 的事。

---

## 0. 为什么先做这个（而不是先迁 HillKing）

我原本的计划是"先让 HillKing 接入 `GameSession`，再做房间"。改顺序的理由：

- HillKing 现在跑在**静态世界**（`world_mini_game` 里的一块区域）。如果现在把它迁到 `GameSession`，
  等房间化之后**还要再迁一次**（世界名从常量变成实例名、区域要随实例改名）。
- **先有房间引擎，HillKing 只需要接一次**：房间 = 世界容器，`GameSession` 挂在房间上。
- 房间引擎本身**不依赖任何游戏**，可以独立编译、独立冒烟、独立验收。

所以顺序是：**R1 房间引擎（本轮）→ R1.5 HillKing 接房间 + GameSession → R2 坐标解耦 → R3 选图 UI**。

## 1. 数据模型

```java
/** 一个模板：设计者编辑好的世界目录，只读，永不被游戏直接加载。 */
record WorldTemplate(
    String gameKey,     // "hillking"
    String mapName,     // "天空竞技场"
    String folder,      // 模板目录名，如 "tmpl_hillking_天空竞技场"
    int    copyBytes    // 缓存体积，用于预算
)

/** 一个房间：模板的一份实例世界，玩家真正玩的地方。 */
final class Room {
    String      roomId;        // "room_hillking_1"
    WorldTemplate template;
    World       world;         // 加载后的 Bukkit World
    long        createdAt;
    long        lastActiveAt;  // 最后有人/有对局的时间，回收用
    boolean     busy;          // 有活动对局（由 GameSession 设置）
}
```

### 目录约定

```
<server>/world/dimensions/minecraft/       ← Paper Moonrise 布局，世界必须在这
    tmpl_hillking_天空竞技场/              ← 模板（设计者编辑；永不加载）
    tmpl_mm_圣诞工厂/
    room_hillking_1/                       ← 房间实例（用完即删）
    room_hillking_2/
```

- 模板也放在同一个父目录下，**但永远不 `createWorld`**（只是被复制的源）。
- 房间名带序号/短哈希，避免和模板、和现有 `world_*` 撞名。
- **模板名以 `tmpl_` 开头、房间名以 `room_` 开头**，靠命名就能分辨（也便于清理脚本兜底）。

## 2. 房间创建流程（7 步，每步失败都要能回滚）

```
1. 检查名额        全服房间数 < maxRooms，该游戏房间数 < maxRoomsPerGame
2. 复制目录        cp -a --reflink=auto <模板> <房间>      ← 绝不能写 --reflink=always（生产是 ext4）
3. 删世界身份      rm -f <房间>/data/paper/metadata.dat
                        <房间>/session.lock
                        <房间>/level.dat_old
4. 加载世界        主线程 Bukkit.createWorld(new WorldCreator(roomId))
                   ⚠️ 必须在主线程；失败则删目录并放弃（不能留半成品）
5. 套规则          按模板声明的 gamerule（pvp/difficulty/mob-spawning/keep-inventory...）
6. 注册区域        把模板声明的 ArenaRegion 复制一份，world 换成 roomId 后注册
7. 记账            登记 Room，doctor 可见
```

**关键约束（都在 AGENTS.md §0.5 里）**：

- `cp` 必须 `--reflink=auto`：开发机 btrfs 白拿 0 拷贝，生产 ext4 自动回落。
- 第 3 步漏掉就会得到 `is a duplicate of another world ... duplicated Paper world metadata`。
- `createWorld` 只能在主线程 → 第 2/3 步（纯文件操作）**应当异步**，第 4 步之后回主线程。

### 并发与排队

派对一次要开多个房间，而 `createWorld` 是主线程串行的。所以：

- 复制/删除 → 异步线程池（唯一允许的异步：纯文件操作）
- `createWorld`/`unloadWorld` → **主线程队列，每 tick 最多处理 1 个**
- 这样 5 个房间 ≈ 5 tick 建完，不会 10 tick 卡顿

## 3. 房间销毁流程

```
1. 检查             没有玩家在这个世界（有的话先传送回主城）
2. 标记              从可创建列表里摘掉（防止边销毁边被选）
3. 卸载世界          主线程 Bukkit.unloadWorld(world, false)   ← save=false：不存盘，反正要删
4. 删目录            异步 rm -rf <房间>                        ← ext4 上 59ms/2个，可忽略
5. 撤销区域          RegionRegistry.unregisterGame(roomId 前缀)
6. 释放名额
```

**`unloadWorld(world, false)` 的 `false` 很重要**：房间世界的数据本来就要丢，
存盘既浪费 I/O 又可能因为"存盘时区块还在写"卡住。反正下一步就删目录。

---

## 4. 回收（防磁盘泄漏，ext4 上的第一号运维风险）

- 每 60 秒扫一次：`now - lastActiveAt > idleSeconds`（默认 300 秒）且 `!busy` → 销毁。
- `busy` 由 `GameSession` 置位（R1.5 接）；R1 阶段先用"世界内玩家数 > 0"判断。
- 每游戏/全服都有上限；达到上限时，创建请求应当**先尝试回收最老的空闲房间**，还不行才拒绝。
- `doctor` 必须显示：房间数 / 各模板占用 / 最老的空置时长 —— 让泄漏看得见。

## 5. 管理命令（R1 的验收入口）

```
/hub room list                    列出所有房间（游戏/模板/年龄/人数）
/hub room create <模板> [名字]     手动建一个房间（R1 的验收手段）
/hub room delete <房间>            手动删
/hub room info <房间>              详情（坐标、占用、最后活动）
/hub room templates               列出可用模板
```

R3 之后这些会被"玩家选图 UI"取代，但**永远保留给 OP 排障**。

## 6. 模板的登记与编辑

- **R1 阶段**：模板由 OP 手动准备 —— 把设计好的世界目录改名成 `tmpl_<gameKey>_<地图名>` 放到位，
  然后在 `templates.yml` 里登记一行：

  ```yaml
  templates:
    hillking_天空竞技场:
      game: hillking
      folder: tmpl_hillking_天空竞技场
      rules: { pvp: true, difficulty: NORMAL, mob-spawning: false, keep-inventory: false }
      regions:
        - { name: "", x1: 620, y1: 40, z1: 300, x2: 700, y2: 90, z2: 380 }
  ```

- **R2 阶段**再加"模板发布"机制（设计者改完 `/hub room template commit`，把编辑目录 reflink 成不可变快照），
  避免"改一半的模板被复制走"。
- 区域的坐标是**模板内坐标**，实例化时世界名替换成房间名 —— 这正是 R2「坐标与世界名解耦」要解决的问题，
  R1 先在模板登记里把坐标写下，等于把这件事的数据结构先定下来。

## 7. 验收（R1 做完必须满足）

1. `tools/build.sh --deploy` 全绿；
2. `tools/smoke.sh --deploy --commands <含 room create/list/delete 的脚本>`
   → `Done (…)`、`ERROR/SEVERE 0 行`、日志里出现房间创建成功与删除成功；
3. 房间目录在创建后存在、删除后不存在（脚本可直接检查）；
4. 手动重复上述三次，**不残留任何 `room_*` 目录**（验证回滚与回收）；
5. `/hub doctor` 新增 `[房间]` 段：房间数/模板数/最老空置。
