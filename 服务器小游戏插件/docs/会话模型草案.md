# 会话模型草案（P1a）

> 这是**接口设计稿**，不是实现。请先审这份，确认语义再动手。
> 目标：让 `docs/框架不变量.md` 的 **I1（玩家归属是一条链）/ I4（生命周期唯一出口）/ I5（状态转移封闭）** 从"靠自觉"变成"写不出来"。
>
> 本轮范围：只落骨架 + 让 **HillKing** 一个游戏接入。**不碰**事件裁决（那是 P2 的 `ListenerGateway`），
> **不做** `GameCatalog`（P1b）。

## 1. 三个类型

```java
package com.hub.session;

/** 对局为什么结束。必填——没有"结束"这个动作就没法区分 ROUND_END 和 PLAYER_QUIT。 */
public enum EndReason {
    ROUND_END,    // 正常打完：记成绩、发奖励
    PLAYER_QUIT,  // 唯一参与者退出：不记成绩，给退出提示
    ADMIN_STOP,   // 管理员手动停：记不记成绩由游戏决定（默认不记）
    ABORT,        // 人数不足 / 出错 / 最后一个玩家离开：不记成绩
    ERROR         // 框架侧异常，尽力收场：不记成绩，记 Failures
}

/** 对局状态。转移表写死在框架里，非法转移抛异常。 */
public enum SessionState {
    CREATED,   // 已创建，还没进等待室
    WAITING,   // 等待室（可加入/退出）
    RUNNING,   // 对局进行中
    ENDING,    // 收场中（正在还原物品/结算）
    ENDED      // 已结束（终态）
}
```

```
CREATED ──► WAITING ──► RUNNING ──► ENDING ──► ENDED
    │           │           │          │
    └───────────┴───────────┴──────────┴──► ENDED（任何状态都能直接 end，但只能一次）
```

## 2. `GameSession`：唯一出口 + 状态机 + 资源持有

```java
package com.hub.session;

public abstract class GameSession {

    // ---------- 身份（创建时固定，不可变）----------
    public final String gameKey();            // "hillking"
    public final String arenaName();          // "" = 单场
    public final GameSession parent();        // null = 根（单开一局）
    public final List<GameSession> children();// 子对局（派对用；HillKing 没有）

    // ---------- 状态 ----------
    public final SessionState state();
    public final boolean isActive();          // != ENDED

    // ==== 生命周期：唯一出口 ====
    /**
     * 结束这个对局。**幂等**：第二次调用只记一条警告，不重复结算。
     * 会依次：① 递归 end 所有子对局 ② 取消本会话持有的全部 BukkitTask
     * ③ 把所有参与者从归属链上摘下来 ④ 调 onEnd(reason)。
     */
    public final void end(EndReason reason);

    // ==== 子类只实现这两个 ====
    /** 进入 RUNNING 之前调一次（发装备、传送到出生点、起计时器）。 */
    protected abstract void onStart();
    /** 收场。必须**按 reason 分流**：只有 ROUND_END 才记成绩。 */
    protected abstract void onEnd(EndReason reason);

    // ==== 状态推进：protected，且受转移表约束 ====
    protected final void enterWaiting();      // CREATED -> WAITING
    protected final void enterRunning();      // WAITING  -> RUNNING（内部调 onStart）
    protected final void enterEnding();       // RUNNING  -> ENDING

    // ==== 参与者 ====
    public final Set<UUID> players();         // 只读视图
    /** 加入。会 attach 到归属链；冲突时不抛给玩家看，记 Failures 并 return false。 */
    public final boolean join(Player p);
    /** 离开（个人退出，不影响对局）。从归属链摘下；最后一个人走了就 end(ABORT)。 */
    public final void leave(Player p);

    // ==== 资源持有（对应你们框架里的 inner_tasks）====
    /** 登记一个 BukkitTask，end 时统一取消。游戏里别再自己存 task 字段。 */
    protected final BukkitTask ownTask(BukkitTask task);

    // ==== 子对局（派对用）====
    /** 创建子对局：自动挂 parent，父 end 时递归。P1a 阶段先不放出来。 */
    protected final <T extends GameSession> T spawnChild(Supplier<T> factory);
}
```

### 三个关键决定的理由

| 决定 | 理由 |
| --- | --- |
| `end()` 是 **final**，子类只能实现 `onEnd` | 子类无法"忘记"取消任务 / 忘记摘归属链。I4 靠**结构**保证，不靠自觉 |
| `end()` **幂等** | 现在到处是"结算了两次/幽灵对局"，根源是没定义重复调用的语义。幂等 + 第二次只警告 = 收敛 |
| 任务由 session 持有（`ownTask`） | 对应你们 `命令框架.md` 3.5 的 `unlock()` 取消 `_inner_tasks`。否则"游戏结束了计时器还在跑" |

### `end(reason)` 的收场顺序（必须固定）

```
end(reason)
 ├─ 若 state == ENDED：只记一条 "重复 end 被忽略" 的警告，return
 ├─ state = ENDING
 ├─ 递归 children().forEach(c -> c.end(reason))     // 父死子必死
 ├─ 取消 ownTasks()                                  // 计时器/倒计时/粒子任务
 ├─ 对每个参与者 PlayerSessions.detach(id, reason)   // 摘归属链
 ├─ onEnd(reason)                                    // 子类收场（按 reason 分流）
 └─ state = ENDED；通知 parent().onChildEnded(this, reason)
```

## 3. `PlayerSessions`：归属是一条链（I1）

```java
package com.hub.session;

public final class PlayerSessions {

    /**
     * 把玩家挂到某个会话上。
     * <ul>
     *   <li>当前无归属 → OK</li>
     *   <li>当前叶子是新会话的**祖先** → OK（嵌套：派对里开小游戏）</li>
     *   <li>其它情况（并列）→ 抛 IllegalStateException（I1 被违反）</li>
     * </ul>
     */
    public static void attach(Player p, GameSession session);

    /** 从链上摘下（按 reason 决定要不要给提示）。 */
    public static void detach(UUID id, EndReason reason);

    /** 玩家当前所在的**叶子**会话；不在任何对局里返回 null（= 在大厅）。 */
    public static GameSession sessionOf(UUID id);

    /** 根 → 叶的完整链（长度 0/1/2）。 */
    public static List<GameSession> chainOf(UUID id);

    /** 玩家主动回大厅（/hub、右键回主城道具）：从整条链上摘下，空了的会话 end(ABORT)。 */
    public static void quitToLobby(Player p);

    /** 一致性自检（冒烟台/doctor 用）：返回发现的违规描述，空列表 = 全链路正常。 */
    public static List<String> audit();
}
```

### 为什么是"链"而不是"至多一个"

派对（`COMPOSITE`）里的小游戏天然是嵌套的：

```
单开：  [hillking#41]            ← 链长 1
派对：  [party#3] ⊃ [hillking#41] ← 链长 2
大厅：  []                       ← 链长 0
```

判定规则只有一条：**链上不能有并列**。框架不关心根是谁。

### `/hub` 那类 bug 在新模型下怎么消失

现在：
```
玩家按 /hub → HubAPI.notifyLobbyHandlers 广播 → 各插件猜"这算不算退出"
             ArcadeParty 猜"不算" → 玩家留在 playing 集合 → 下轮 performCommand(join) 又拉回来
```

新模型：
```
玩家按 /hub → PlayerSessions.quitToLobby(p)   // 框架动作，不是广播
             ├─ 沿链从叶到根 detach
             ├─ 空了的会话 end(ABORT)
             └─ 玩家归属变空 = 在大厅
```

**没有"猜"这个环节**：退出就是摘链，摘了就不会再被算进下一轮的参与者。

## 4. 三条不变量在这一步怎么落地

| 不变量 | 靠什么保证 | 怎么验 |
| --- | --- | --- |
| **I1** 归属是一条链 | `attach` 只在"无归属"或"祖先后代"时通过，否则抛异常；`chainOf` 只能有一条链 | `PlayerSessions.audit()` + 随机 join/leave/hub 序列断言 |
| **I4** 生命周期唯一出口 | `end` 是 final + 幂等 + 固定收场顺序；`teleportToLobby` 不再承担"退出"语义 | 每个 session 恰好一次 `end`；`audit` 里无 "ENDED 但仍挂着玩家" |
| **I5** 状态转移封闭 | `state` 私有，只能经 `enterXxx`/`end` 改；转移表写死 | 每个非法转移一条单测；非 RUNNING 状态调用 `onStart` 直接抛 |

## 5. HillKing 接入草图（第一个吃螃蟹）

现状（简化）：

```java
private boolean running;
private BukkitTask timer;
private final Set<UUID> players = new HashSet<>();

public void startGame() { if (running) return; running = true; timer = ...; }
public void stopGame()  { running = false; timer.cancel(); award(); teleportAll(); }
```

改造后：

```java
final class HillKingSession extends GameSession {
    HillKingSession(...) { super("hillking", ""); }

    @Override protected void onStart() {
        ownTask(Bukkit.getScheduler().runTaskTimer(plugin, this::tick, 0L, 20L));
        teleportToSpawns();
    }

    @Override protected void onEnd(EndReason reason) {
        // 只有 ROUND_END 才记成绩
        if (reason == EndReason.ROUND_END) Top3.award(stats, firsts, seconds, thirds);
        teleportAllToLobby();      // 注意：这是"人走"，不是"对局结束"
    }
}
```

`HillKingManager` 里：
- `startGame()` → `session.enterRunning()`
- `stopGame()` / 时间到 → `session.end(ROUND_END)`
- 玩家加入 → `session.join(p)`
- 玩家离开 → `session.leave(p)`
- `onDisable` → `session.end(ADMIN_STOP)`

**行为应当零变化**（这是迁移的第一个验收点）：除了"重复 start 会被拒绝"和"退出后不会再被算回来"。

## 7. 需要你拍板的三个点

1. **`end` 重复调用是警告还是抛异常？**
   我倾向**只警告**（幂等），因为现实中"时间到"和"最后一人退出"可能同时触发；
   抛异常会让玩家看到报错。但如果你的风格是"错就要响"，改成抛也合理。

2. **`attach` 冲突时：抛异常 vs 静默拒绝？**
   我倾向**抛给调用方**（框架内部），但 `GameSession.join()` 捕获后记 `Failures`、给玩家一句提示、返回 false——
   即"程序错误要留痕，玩家体验不能崩"。你同意这个分层吗？

3. **HillKing 是第一个接入者，要不要连带把它那个"离台不传送"的既有行为做一遍回归？**
   我建议**要**：迁移前后各跑一次冒烟 + 你进游戏验一次，确认"玩法零变化"。
   这样后面 22 个游戏迁移就有可复制的验收流程。

## 补充（2026-11-01）：什么时候真的需要子 session

用户追问了一个好问题：既然"单局小游戏可以包装成只有一个游戏、没有领奖流程的派对"，
那还需要"父 session ⊃ 子 session"这套嵌套吗？能不能砍掉以降低复杂度？

### 判断只有一条

> **父 session 是否必须比子 session 活得久？**

| 形态 | 父比子活得久？ | 需要嵌套？ | 会话树 |
| --- | --- | --- | --- |
| 单局游戏（`SINGLE`） | — | ❌ | 1 个 session |
| **单局包装成派对**（`PARTY_OF_ONE`） | ❌ 游戏结束 = 整局结束 | ❌ | **1 个 session（和上面同一条路径）** |
| 多局派对（`PARTY_MULTI`） | ✅（第 1 局结束后还要开第 2 局、还要累计分数/淘汰） | ✅ | 父 + N 个子 |

所以：

- **"派对"不是一种 session 类型，而是房间的一种「编排属性」。**
  它决定的是**流程/UI**（有没有领奖台、有没有"下一局"、是否有跨局累计），
  而不是**结构**（要不要多一层 session）。
- `SINGLE` 与 `PARTY_OF_ONE` **共用同一条代码路径**：一个房间、一个 session、
  一个 `end(reason)`。差别只在展示层。
- 只有 `PARTY_MULTI` 才用 `COMPOSITE` 父子，理由是**父必须活过子**——
  第 1 局的小游戏结束（`ROUND_END`）时，派对本身**不能结束**。

### 因此可以砍掉的复杂度

1. **单局游戏不再创建父 session**：少一层状态机、少一次"收场递归"。
2. **`PlayerSessions` 的 depth-2 逻辑只服务 `PARTY_MULTI`**：
   I1 里"链长 2"的场景从"所有派对"缩小到"多局派对"，单局永远是链长 1。
3. **UI/流程不分叉**：单局房间和派对房间共用同一套"房间 + 一个正在进行的对局"，
   只是派对的房间多几个钩子（下一局、领奖台）。

### 但要保留的能力

`GameSession` 里的 `parent` / `children` / `adopt` **不要删**——
`PARTY_MULTI` 迟早要用（D15 已确认派对要做）。
它们的代价已经付过（P1a 已实现），且对单局路径是**零开销**（子树永远为空）。
正确的做法是：**机制保留，但单局路径不启用它**，并在文档里写死"什么时候才允许用"。

> 一句话：**嵌套是给"父活过子"用的，不是给"派对"这个词用的。**
> 把派对当成编排属性而不是嵌套层数，单局就能走最平的那条路。
