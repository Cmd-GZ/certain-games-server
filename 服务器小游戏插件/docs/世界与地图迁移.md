## 4. "坐标对得上"是怎么验的

1. **离线 Anvil 扫描**（`.server/tools/mca_scan.py`，直接读 `.mca`，不起服）：
   对每张图，源世界"区域盒子"里的非空气方块数 == 目标模板同一盒子（含偏移）里的数，**逐张完全相等**：
   1227006 / 458512 / 114182 / 301430 / 429962 / 395633 / 4799 / 155 / 24759 / 1457 / 729 / 0 /
   13240(+4000) / 10510(+8000) / 1378(+12000) / 441(+16000) / 4165 / 26917（基底与派对集合区）。
   跑法：`bash .server/tools/verify_maps.sh`。
2. **建房实测**（`/gw create room <模板>` + `/rprobe <房间世界> <该图出生点>`）：13 个模板各建一个房间，
   17 个探针里 **15 个"脚下正好是实体方块、落差 0"**：
   双岛 sea_lantern/28、废墟 sea_lantern/166、圣诞工厂 stripped_oak_log/79、ship spruce_planks/109、
   档案室 oak_planks/68、重锤 oak_log/-1、相扑 black_stained_glass/58、足球场 diamond_block/-5、
   糖果屋 oak_log/69、hillking red_wool/52、群系 grass_block/3、tntrun snow_block/38、
   玻璃 glass/100、万箭齐发 ice/37。`tmpl_lp` 探针为空气（**预期**：柱子运行时生成）。
   另 2 个点测出来落在方块里/空档（红地板 y=127 就是地板、别墅中心在建筑空档），
   已把 maps.yml 的 `entry` 改成该场地自己的 spawn / 等待区（红地板 y=128、别墅 -143.49/136/312.5）。
3. **冒烟前后对拍 34 个 `plugins/*/config.yml`**：数据结构 **0 变化**（R2 守卫生效，不再擦坐标）。
4. **基线冒烟**：`33 插件 / ERROR 0 行 / [房间] 模板 13 个 / [地图] 已登记 23 个游戏 / 28 张地图`，

## 5. 删不掉 / 不确定的

- **`world_htf` 保留**（13MB，内容 y 48..79）。HTF 是 git submodule，`paper-hold-the-fort` 的
  `config.yml` 里写的是 `world: world`（主城）+ 自己的 arena 逻辑，**没有**引用 `world_htf`；
  但它是 VOID 世界且有 HTF 场地，属于"还没接模板"的那一类 → 等它接入模板再删。
- **`the_nether` / `the_end` 删过又被 Paper 重建了**（主城的下界/末地维度，开服即按需生成，各 2.2MB 原版地形）。
  想彻底不要它们得改世界配置，不在本次范围。删掉的旧副本本来也是 2.2MB 的空白世界，没内容损失。
- 已删的空壳世界：`0Void World`（1 个方块）、`persmap` / `0BB-Candyland` / `0MM-SantaFactory`（只有地板或**一个方块都没有**）、
  `world_fb` / `world_wf`（只有超平坦地板）。
- **`区域归属表.md` 已经过时**：`tools/region-report.py` 不认 `tpl:` 令牌，重跑会生成一份几乎是空表
  （我试过，已回退）。要更新得先给这个工具加"`tpl:<模板>` → 模板世界"的映射。

## 7. 要你拍板的（我没擅自动）

1. **GTB「糖果屋」盒子太小**：声明的 region 是 27×27 建造台（x -30..-4, z 4..30, y=69），
   但整座糖果屋建筑在 x≈-66..-2、z≈-36..34、y 64..159（~1.1M 方块，含超平坦地板）。
   我只复制了建造台 → 玩家脚下 3 格是原木台，四周是虚空。**要我把整座房子也复制进来吗？**
2. **方块实体（容器/告示牌/头颅/旗帜）只复制了方块、没复制 NBT**（`rcopy` 是 `Block#setBlockData`）：
   MM 四张图 748+139+512+183 个、双岛 12、足球场 4、群系 10 —— 告示牌文字会变空、头颅变默认皮肤、
   箱子/潜影盒是空的、旗帜花纹丢失。需要的话我另写一个带 TE 的复制（会慢不少）。
3. **相扑的方块还留在主城里**（`overworld`），我只是把它复制成了 `tmpl_duel_sumo` 并把 DuelArena 的
   `相扑` 场地指向模板。要不要把主城里那圈清掉？
4. **模板键命名**：我按"目标模板键/目录"用了 `tmpl_xxx`（key == 目录名）。如果你更想要短键
   （`mini_games` / `mm_xft` …，目录仍是 `tmpl_*`），是一次机械改名，说一声我改。
5. **游戏开局前的"场地未就绪"警告**：现在大多数游戏开服时都会 WARN 一句"场地未配置完整"，
   因为 `tpl:` 令牌要**有存活房间**才解析得出来（框架设计如此）。也就是说这些游戏只能从房间进
   （`/hub create` → `/gw create room`），不能再像以前那样在常驻世界里直接 `/xxx join`。
   这符合这次重排的方向，但如果还有"不进房间也要能玩"的游戏，得单独处理。
6. **DevTools 仍然是 `.build-skip`**（不进 `tools/build.sh` 产物）。我把它的 jar 手动拷进了
   `run/plugins` 和 `.server/deploy/plugins/`，所以现在基线是 **33 个插件**（31 个构建产物 + HTF 旧 jar + DevTools）。
   要不要把它改成正式模块由你定。
